1. どのファイルが何か

拡張子は 2 種類。.difypkg が 1 つ（プラグイン＝処理する部品）、 .yml が 2 つ（アプリ＝画面と流れ）です。入れ方がそれぞれ違います。

覚え方

.difypkg = エンジン（Dify 全体に 1 回入れる）／.yml = 車体（アプリごとに入れる）。 エンジンが入っていない状態で車体だけ入れると、アプリを開いたときにツールのノードがエラーになります。順番は .difypkg が先です。

3. exec について（正直な説明）

情報システム部門がコードを検査すると、まずここが引っかかります。隠さず先に説明します。

exec は「自分で貼り付けた Python を動かす」ためだけに使っています

このプラグインの目的そのものが「Jupyter Lab の代わりに Dify で自分の Python を動かす」ことなので、 コードを実行する処理は機能の中核であって、隠された裏口ではありません。 Jupyter Lab でセルを実行するのと同じ性質のものです。

確認したいこと実際
どこにあるかcore_logic/core_runner.py の execute_code() 1 箇所のみ
何を実行するかDify のワークフローの環境変数（CORE_CODE / PYTHON_CODE）に自分で貼り付けたコードだけ
外部から注入される経路はない。実行するコードの受け取り口はワークフロー定義で環境変数に固定されており、チャットの入力文やアップロードしたファイルがコードとして実行されることはない
誰が書き換えられるかそのワークフローを編集できる Dify のユーザーだけ（＝ Dify の権限設定に従う）
実行される場所社内 Dify のプラグイン用コンテナの中。外へは出ない

該当箇所は全部で 4 行です。ここだけ読めば、何を実行しているかが確認できます。 

compiled = compile(code_text, f"<{error_label}>", "exec")
with contextlib.redirect_stdout(buffer), contextlib.redirect_stderr(buffer):
    exec(compiled, module.__dict__)          # ← 貼り付けたコードを実行
    main = module.__dict__.get("main")       # main() があれば呼ぶ

redirect_stdout で print の出力を横取りして画面に表示しているだけで、 実行結果を外部へ送る処理は含まれていません。

4. 自分で検証する

こちらの説明を信用せずに、手元で同じ検査を再現するための手順です。

中身を全部見る

# ZIP として展開して、入っているファイルを全部並べる
unzip -o plan_automation.difypkg -d pkg
find pkg -type f | sort

Windows なら拡張子を .zip に変えてエクスプローラーで開けば同じです。

危険な処理が無いことを確認する

# 外部通信（0 件になるはず）
grep -rnE "import (requests|urllib|socket|http|smtplib)" pkg --include=*.py

# OS コマンド実行（0 件になるはず）
grep -rnE "subprocess|os\.system|os\.exec|popen" pkg --include=*.py

# 難読化・隠しコード（0 件になるはず）
grep -rnE "base64|marshal|pickle|__import__" pkg --include=*.py

# コード実行（core_runner.py の 1 箇所だけ出るはず）
grep -rnE "\b(eval|exec)\(" pkg --include=*.py

受け取ったファイルの同一性を確認する

sha256sum plan_automation.difypkg
# Windows: certutil -hashfile plan_automation.difypkg SHA256

出た値が 2 章のハッシュと一致すれば、受け渡しの途中で変わっていません。

5. 導入手順

上から順に。1 と 2 は最初の 1 回だけ、3 以降はアプリごとに行います。 画面の文言は Dify のバージョンで多少変わりますが、位置は同じです。

  1. 署名検証をオフにするセルフホストのみ

    Dify は既定で「署名のないプラグイン」を拒否します。自前で作ったプラグインは署名がないため、 先にこの設定を入れないとインストールで弾かれます。 クラウド版（cloud.dify.ai）を使っている場合はこの手順は不要です。

    Dify を動かしているサーバーの docker/.env に 1 行追加して、再起動します。

    FORCE_VERIFYING_SIGNATURE=false
    cd docker
docker compose down && docker compose up -d

  2. プラグインをインストールする

    ここが今回いちばん分かりにくいところです。アプリの中ではなく、Dify 全体の設定側から入れます。

    画面右上のメニュー → プラグイン → 「プラグインをインストールする」 → ローカルパッケージファイル

    ファイル選択で plan_automation.difypkg を指定するとインストールが始まります。 このとき Dify が requirements.txt に書かれたライブラリ （dify_plugin / openpyxl / pandas / numpy）を取得するため、少し時間がかかります。

    完了後、プラグイン一覧に Cash Plan Automation が出れば成功です。

  3. アプリ（.yml）をインポートする

    スタジオ → 「アプリを作成する」 → 「DSL ファイルをインポート」

    使いたい方の .yml を選びます。両方入れても構いません。

    • plan_automation_workflow.yml … 資金計画アプリ
    • python_runner_chatflow.yml … Python 実行アプリ

    インポート後、ツールのノードに赤いエラーマークが出ていたら、 ノードを開いてツールを選び直し、入力の割り当てを付け直してください （プラグインの ID がインポート時に解決されないことがあるためです）。

  4. 社内の Python コードを貼り付ける

    コードはリポジトリにもファイルにも入っていません。ここで初めて社内 Dify の中に入れます。

    ワークフロー編集画面 → 環境変数（ENV）
    • 資金計画アプリ … CORE_CODE に資金計画プログラムを貼り付け
    • Python 実行アプリ … PYTHON_CODE に動かしたいプログラムを貼り付け

    書き換えるのは入出力パスのハードコード部分だけです （input_path / output_dir という変数が最初から使えます）。 空のままでも動作確認用のサンプル処理が動くので、先に手順 5 まで通してから貼っても構いません。

  5. 公開して実行する

    右上の「公開する」を押してから「アプリを実行」。 資金計画アプリはフォーム、Python 実行アプリはチャット画面が開きます。

    最初は同梱のサンプル（sample_source_R7.xlsx と 手順書_資金実績まとめ.txt）で 通しの動作を確認してから、実データに移るのが安全です。

6. 完成後の姿

導入が終わると、社内 Dify の中だけで次のように処理が回ります。

利用者
元データ Excel と手順書をアップロード ／ または チャットにファイルを添付
↓
プラグイン
手順書のとおりに Excel から抜き出して、入力用の 1 枚にまとめる
↓
貼り付けたコード
環境変数の Python を実行 （print の出力をそのまま回収）
↓
利用者
Jupyter 風の実行レポートを見て、出力ファイルをダウンロード

データもコードも社内 Dify のコンテナの中で完結し、外部への通信は発生しません。

7. 事前に確認すること

安全性とは別に、社内の環境やルール次第で引っかかる可能性がある点です。

インストール時に外部からライブラリを取得します

プラグインのファイル自体にライブラリは入っていません。インストールの瞬間に Dify が PyPI から dify_plugin / openpyxl / pandas / numpy を取得します。 Dify のサーバーが外部に出られない閉域環境だと、ここで失敗します。

社内 PyPI ミラーがあればそちらに向ける設定で解決できます。 完全な閉域の場合は別の渡し方が必要になるので、その旨をお知らせください。

DSL をエクスポートすると、貼り付けたコードも一緒に出ます

環境変数の値はワークフローの定義に保存されます。つまり CORE_CODE / PYTHON_CODE にコードを貼った後に Dify から DSL を エクスポートすると、その .yml に社内のコードが含まれます。

配布した .yml は環境変数が空のテンプレートなので問題ありませんが、 運用開始後にエクスポートしたファイルの扱いにはご注意ください。

Excel 抜粋エディタ（手順書を作るツール）について

手順書はブラウザで okadamasayuki.github.io/excel-editor を開いて作ります。 処理はすべてブラウザ内で完結し、Excel の中身はどこにも送信されません。

社内から外部サイトを開けない場合は、そのリポジトリの docs/index.html を 1 ファイル持ち込んでダブルクリックで開けば、同じものがオフラインで動きます。
